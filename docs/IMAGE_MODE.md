# 画像モード (テクスチャ再生方式、試作)

ブロックモードとは別のアドオンを作ります。動画の全コマを PNG のアトラス (シート) にしてリソースパックに入れ、板状のスクリーンのエンティティに表示します。コマの切り替えはクライアントの Molang が自分の時計で行うので、30 fps で再生できます (ブロックモードは 20 fps まで)。ブロックモードの変換・再生・データ形式は変えていません。PC (Windows 11) の実機で動作を確かめました (v6.37.0。README のジャンル別の GIF)。

```bash
python convert_image_mode.py video.mp4 -o video_image.mcaddon --width 256 --height 144 --fps 30 --start 0 --end 20 --method both
```

Windows 版の画面とブラウザ版では、「画像モードのアドオンも作る」にチェックを入れると、ブロックモードのアドオンの隣に別のファイル (`<名前>_image.mcaddon`) を作ります。コマンドの接頭辞はブロックモードの接頭辞に `_img` を付けたもの (例: `/badapple_img:setup` → `/badapple_img:start`) で、2 つのアドオンを同時に入れてもぶつかりません。.vox と MMD は元の映像のコマが無いので使いません。作れなかったときはログに理由を出し、ブロックモードのアドオンはそのまま残ります。

| | Windows 版 | ブラウザ版 |
|---|---|---|
| 1 コマの大きさ | 横 256 画素、縦は画面の縦横比から | ブロックモードと同じコマ (幅 × 高さの画素) |
| fps | 30。テクスチャが予算を超えたら 15 → 10 に下げて作り直す | ブロックモードと同じ fps |
| 音声 | ffmpeg で 4 秒ごと | ブロックモードと同じ 10 秒ごとの OGG |
| 対応する Minecraft | 1.26.10 以降 | 1.26.10 以降 (古い版向けを選んでいるときは作らない) |

ゲーム内: `/bvpimg:setup [動画ID]` → `/bvpimg:start`。ほかに `play <動画ID>`・`pause`・`resume`・`stop`・`seek <秒>`・`volume <0〜100>`・`stats`・`list` (`/scriptevent bvpimg:<操作>` でも可)。
**時計**を使うか `remote` で、ブロックモードと同じリモコンが開きます (ブロックモードのリモコンはコンパス)。`setup` には `face` (向きを東西南北にそろえる)・`wall` (見ているブロックの横の面に貼る)・`align` (ブロックの格子にそろえる) を付けられます。メッセージは 10 言語です。

## 角度で絵を切り替える立体 (試作)

入力に `.vox` (MagicaVoxel の立体・立体アニメ) を渡すと、立体をまわりの 8 方向 (`--views`、45 度ごと) から描いた絵にして、見る人の角度に一番近い絵を、その人のほうへ向けた板に映します。歩いて回り込むと、正面・横・後ろの絵に切り替わり、立体が立っているように見えます。見る人ごとに自分の角度の絵が出るので、マルチプレイでも全員にそう見えます。

```bash
python scripts/make_demo_dancer.py dancer.vox
python convert_image_mode.py dancer.vox -o dancer_image.mcaddon --height 128 --figure-blocks 6
```

- 1 マスの高さは `--height` (画素)、幅は立体のどの向きでも入るように決まります。`--figure-blocks` はゲームの中の高さ (ブロック)、`--fps` の既定は 10 です。
- 背景は透明 (アルファテスト) で、面の明るさは Minecraft のブロックと同じ割合 (上 1.0・横 0.8 / 0.6・下 0.5) を描くときに付けます。光は立体に固定なので、回り込んでも光の向きは変わりません。
- 音声は無く、終わりまで行くと頭へ戻って繰り返します。`/bvpimg:setup <ID>` → `/bvpimg:start` はほかの動画と同じです。
- 限界: 向きの境目 (45 度ごと) で絵がぱっと切り替わる。上下の角度は見ないので、真上・真下からは平らな絵に見える。テクスチャが向きの数だけ増える (`dancer` の 40 コマ × 8 方向で 15 MiB)。方式 a だけ・PNG だけ・`--dedup` と `--priority` は使えません。動画と同じアドオンには入れられません。
- PC (Windows 11、Minecraft 1.26.63) の実機で、正面・45 度ごと・後ろから、向きに合った絵がこちらを向いて映ること、踊りが繰り返すことを確かめました (2026-11-17)。スマートフォン・マルチプレイは未確認です。ブラウザ版・Windows 版の画面にはまだ出していません。
- 角度の求め方と符号の決め方は DECISIONS.md の A18、作り方は `image_mode/impostor.py`。

## ガラスケースの立体 (試作)

立体を「ボクセルの外に出ている面」の板にして置きます (設計: [research/glass_case.md](research/glass_case.md))。板はゲームが見る人ごとに描くので、回り込んでも、上や斜め下から見ても、本物の立方体と同じ形に見えます。角度ごとの絵 (上の節) のように絵が切り替わることはありません。周りにケースを置くと、手前の壁は透けて、奥の壁だけが背景として見えます。

```bash
python convert_image_mode.py dancer.vox -o dancer_case.mcaddon --case --case-image back=bg.png --figure-blocks 6
python convert_image_mode.py dancer.vox -o show.mcaddon --case --case-video mv.mp4      # 奥の壁で動画 (音声付き)
python convert_image_mode.py mv.mp4 -o relief.mcaddon --lift relief --case --end 20      # 動画を浮き彫りにして置く
```

| オプション | 内容 |
|---|---|
| `--solid planes` | 面の板にする。`--case`・`--case-image`・`--case-video`・`--case-frame`・`--lift` を付けると自動で planes (既定の views は上の節の角度ごとの絵) |
| `--plane-split rect\|tile8\|tile16` | 板の分け方。`rect` (既定) は平面ごとに 1 枚。`tile8` は透明な所とテクスチャが減るが、板が十数倍に増える |
| `--case` / `--case-margin` / `--case-frame` | 床と 4 枚の壁 (人物との間は既定 0.5 ブロック) / 12 本の縁 |
| `--case-image SIDE=PATH` | 壁と床の絵。SIDE は `back`・`front`・`left`・`right`・`floor`・`all`。渡さない所は暗い色 |
| `--case-video VIDEO` | 奥の壁の内側で動画を流す。音声もこの動画。大きさは `--width`・`--height`、fps は `--case-video-fps` (既定 30)。人物は同じ時計で自分の fps (`--fps`、既定 10) で繰り返す |
| `--lift relief\|extrude\|inflate` | 入力の動画を、ブロックモードと同じ方法で浮き彫りの立体にする (`--lift-size` 既定 128x72、`--depth` 既定 16、`--depth-video`・`--mask-video`)。正面から斜めまでは立体、横からは薄く、後ろからは平ら |
| `--max-figure-frames` | 人物のコマ数の上限 (既定 240) |
| `--face-mapping N,E,UU,UV` | 板の UV の向き (試験用。既定は実機で決めた `1,-1,1,-1`) |

- `/bvpimg:setup <ID>` で、目の前の床にケースを立てます (`face`・`align` も使えます。`wall` を付けても壁には貼らず、目の前に置きます)。
- 大きさの目安 (変換ツールで測った値): 踊る人物 (高さ 128 ボクセル・40 コマ) で板 7,715 枚・テクスチャ 31.5 MiB。動画の浮き彫り (128x72・奥行き 16) で 1 コマ板 126 枚・約 0.56 MiB (`tile8` なら 1,900 枚・約 0.39 MiB)。
- PC (Windows 11、Minecraft v26.65) の実機で、人物が前・横・後ろ・斜め上から立方体に見えること、ケースの手前の壁だけが消えて残りの壁の絵が鏡写しにならないことを確かめました (2026-11-18)。板の UV の向きは、`python scripts/make_planes_test_pack.py planes_test.mcaddon` の試験用のアドオンの 16 通りから選びました (DECISIONS.md の A19)。スマートフォン・マルチプレイ・重さ (fps と読み込み時間)・遠くからの見え方は未確認です。
- 限界: 入力はボクセル (`.vox`)、動画の浮き彫り、MMD のモデル (下の節)。光の向きは立体に固定。透明は「あり・なし」の 2 段。`.vox` は音声なしで繰り返し再生。

### MMD の人物を骨で動かす (試作)

MMD のモデル (`.pmx`) を入力にすると、人物を初期姿勢で 1 回だけボクセルにしてボーンごとの部品に分け、踊り (`.vmd`) はボーンのアニメーションにします (設計: [research/glass_case_practical.md](research/glass_case_practical.md))。コマごとに板を持たないので、1 曲を通してもテクスチャは 1〜2 MiB で、動きは描画のたびになめらかに補間されます。

```bash
python convert_image_mode.py model.pmx --motion dance.vmd --audio song.wav --case --case-image back=stage.png -o show.mcaddon
python convert_image_mode.py model.pmx --motion dance.vmd --case --case-video mv.mp4 --priority quality -o show.mcaddon
```

| オプション | 内容 |
|---|---|
| `--motion VMD` | 踊り。無ければ動かない人物 |
| `--audio FILE` | 曲。曲の長さだけ再生し、踊りが短ければ最後の姿勢で止まる (長ければそこで切る)。`--case-video` と一緒なら、壁の動画の音声の代わりに鳴らす |
| `--figure-voxels N` | 細かさ (初期姿勢の高さのボクセル数、既定 128)。大きさは `--figure-blocks` (既定 6 ブロック) |
| `--joint-overlap N` | 関節で隣の部品に重ねるボクセルの数 (既定 1)。重ねるのはウェイトが 2 本のボーンに分かれている所だけ |
| `--figure-loop` | 踊りを繰り返す |
| `--priority` | `--case-video` があるとき、人物とケースの絵を除いた予算 (`--target-tier`) に壁の動画が収まるよう、壁の動画の fps・大きさ・長さを下げる |

- 踊りで動かないボーン (物理の髪・スカートなど) は親にまとめます。IK・付与・センターの移動は、変換ツールが解いた姿勢を焼き込みます。その場で踊らせます (センターの前後左右の移動を消す。上下は残す)。ケースは、踊りの間に人物が通る範囲に合わせます。
- ボーンの回転の向きと順番は PC の実機で決めました (DECISIONS.md の A20)。移動 (センターの上下など) の向き、関節のすき間、陰、1 曲を通したときの重さと同期は、まだ実機で見ていません (docs/TESTING.md の 6)。
- MMD のモデル・踊り・曲には作者の利用規約があります。規約で許された範囲で使ってください。作ったアドオンを人に配れるかも規約しだいです。
- 画面 (Windows 版) とブラウザ版にはまだありません。

## 明るさ・縮め方・シートの詰め方

| オプション | 既定 | 内容 |
|---|---|---|
| `--lighting bright\|world` | `bright` | `bright` は周りの光と陰で暗くならない (render controller の `ignore_lighting`)。実機で、昼も夜も同じ明るさになることを確かめた。`world` は v6.36.0 までと同じ (夜はほぼ見えない) |
| (縮め方) | — | Windows 版・コマンドラインは、元の動画をコマに縮めるとき面積平均 (`flags=area`) で縮める。テスト映像で PSNR 37.26 → 37.38 dB、パック −24%。拡大は今までどおり。ブラウザ版の画像モードはブロックモードと同じコマを使うので、ブロックモードの出力を変えないよう、縮め方は v6.36.0 のまま |
| `--snap` / `--no-snap` | 使う | 頼んだ大きさの 9 割以上で、元の動画をちょうど割り切れる大きさにして、シート 1 枚に入るコマを増やす (1920×1080 で 512×288 → 480×270、シート 18 → 13 枚、テクスチャ −15%、パック −12%)。画質は既定と同等以上: テスト映像で PSNR 37.38 → 37.63 dB、粒子を足した実写に近い映像で 37.67 → 37.81 dB (SSIM は ±0.0006)。割り切れない大きさ (510×286 など) は輪郭のはっきりした映像で −1.6 dB になるので選ばない。元の大きさが分からない・縦横比が違う・1 割より大きく縮めないと増えないときは、頼んだ大きさのまま。ブラウザ版はコマの大きさが決まっているので使わない |
| `--png-optimize` | 切る | シートの PNG を最適化 (パック −3%、変換が数倍遅い) |
| `--sheet-format png\|jpeg`、`--jpeg-quality` | png | シートを JPEG (4:4:4、品質の既定 92) にする。実写 2 本 (Tears of Steel、512×288・24 fps・8 秒) で、パック −74% / −72%、元の映像との PSNR −0.84 / −0.66 dB。GPU のメモリ (予算) は変わらない。アニメや文字は縁がにじみやすい。PC で映ることは確かめた (v6.37.0)。スマートフォンは未確認。画面とブラウザ版には出していない (v6.38.0 から)。図形や文字の多い映像は PNG のほうが小さいので、PNG のほうが小さいシートは jpeg を選んでも PNG のままにする (シートごとに決める。レポートの `sheet_files`) |
| `--dedup off\|exact\|near`、`--near-threshold` | off | 同じ絵のコマを 1 マスにまとめて、テクスチャを減らす。コマからマスを引く表は、クライアントの Molang で区間の二分探索 (`image_mode/dedup.py`。区間が 2048 を超えるか、省けるマスが 3% 未満ならまとめない)。exact はまったく同じコマだけで、圧縮された動画では同じ絵でも画素が少し違うので、ほとんど効かない。near (すぐ前に残したコマとの差の平均が 1.0 以下) は、512×288・24 fps・12 秒で: 2 コマ打ちの合成映像 シート 14 → 7 枚 (−50%)、デモ 14 → 13 枚 (マス −12%)、猫の実写 14 → 13 枚 (マス −11%)。まとめない出力との PSNR 43.7〜44.2 dB。Minecraft での確認がまだなので既定は off (v6.38.0 から) |

Windows 版の画面では「明るさ」「シートに多く詰める」「PNG を最適化」、ブラウザ版の画面では「明るさ」「PNG を最適化」を選べる。

動画のメタデータの `lighting` が無い (v6.36.0 までの) アドオンは `world` として扱う。`image_main.js` は変えていない。

## 予算を超えるとき (何を優先するか)

`--priority quality|smooth|length` (Windows 版は「優先」の選択) で、テクスチャが予算 (`--target-tier`、既定 2) を超えるときに何を守るかを決めます。

| 優先 | 変えるもの | 例: 512×288・30 fps・60 秒を Tier 2 (225 MB) に |
|---|---|---|
| 画質 (quality) | fps を下げる。足りなければ後ろを切る | 512×288・10 fps・約 38 秒 |
| なめらかさ (smooth) | コマを小さくする | 226×128・30 fps・60 秒 |
| 長さ (length) | fps とコマを交互に下げる | 314×176・15 fps・60 秒 |

計算は image_mode/budget.py (動画を読まずに数える)。Windows 版では「1 つのファイルにまとめる」で、ブロックモードの .mcaddon の中に画像モードのパック (`BP_image/`・`RP_image/`) も入れられます。ブラウザ版はまだどちらも選べません (コマはブロックモードと同じ大きさ)。

## 方式 A と方式 C

既定は方式 A だけです (2026-11-12 の実機の確認で A に決めました)。`--method both` で両方のエンティティを入れると、`/bvpimg:method a|c` で同じ場所・同じ再生位置のまま切り替えて見比べられます。テクスチャは共有します。

- **方式 A** (既定): アトラス + textures 配列 + 1 マス 1 ボーン + part_visibility。マテリアルを変えず、文書にある機能だけを使います。マスの数だけボーンがあり、その負荷は未確認です。
- **方式 C**: `USE_UV_ANIM` を足した自作マテリアル (`bvp_uv_anim:entity_alphatest`) + uv_anim。ボーンは 1 本です。
  **⚠ 将来の Minecraft の更新で壊れるリスクがあります。** Microsoft Learn は自作マテリアルについて「将来、非推奨または削除される可能性がある」と書いており、Vibrant Visuals で動くかも未確認です。

## テクスチャメモリ

テクセル数 × 4 バイトで数えます (Microsoft Learn の Texture Budgets)。変換時に Tier ごとのアドオンの予算 (Tier 1 150 MB 〜 Tier 5 800 MB) と比べた表を出し、Tier 2 (多くのスマートフォン・PS4・Xbox One) を超えると警告、Tier 5 を超えると `--allow-over-budget` が無ければ止めます。例: 256×144・30 fps・20 秒で約 97 MiB。

## 同期と限界

スクリプトは 1 秒ごとに「今のコマ」と通し番号をエンティティのプロパティに書き、クライアントはそこから自分の時計で進めます。チャンクの読み直しやワールドの開き直しの後は、最後に書いたコマから進め直し、次の書き直し (1 秒以内) で戻ります。時計はスクリプトが再生中に数える実時間 (tick ごとの `Date.now()` の差。1 tick で 250 ms まで) で、1 秒ごとに保存するので、開き直すと続きから戻ります (眠る・`/time set` の影響を受けず、TPS が下がっても音声と映像がずれません。v6.37.1 までは tick の数で数えていました)。途中で入ってきた人がいると、そのときにもコマを書き直します。音声は 4 秒ごとのチャンクで、途中からは鳴らせないため、シークは近いほうのチャンクの頭へ (近いほうの頭が動画の終わりより後なら、そろえずに頼んだ所へ行き、終わりまで無音)、再開は止めた所を含むチャンクの頭へそろえて、すぐに音を鳴らします。開き直しと途中参加の後は、次の境目まで無音です。

詳しい取り決めは [image_mode/SPEC.md](../image_mode/SPEC.md)、調査の根拠はフェーズ 1 の報告にあります。
