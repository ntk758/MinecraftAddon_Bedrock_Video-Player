# 画像モード (テクスチャ再生方式、試作)

ブロックモードとは別のアドオンを作ります。動画の全コマを PNG のアトラス (シート) にしてリソースパックに入れ、板状のスクリーンのエンティティに表示します。コマの切り替えはクライアントの Molang が自分の時計で行うので、30 fps で再生できます (ブロックモードは 20 fps まで)。ブロックモードの変換・再生・データ形式は変えていません。**実機ではまだ確かめていません。**

```bash
python convert_image_mode.py video.mp4 -o video_image.mcaddon --width 256 --height 144 --fps 30 --start 0 --end 20 --method both
```

Windows 版の画面とブラウザ版では、「画像モードのアドオンも作る」にチェックを入れると、ブロックモードのアドオンの隣に別のファイル (`<名前>_image.mcaddon`) を作ります。コマンドの接頭辞はブロックモードの接頭辞に `_img` を付けたもの (例: `/badapple_img:setup` → `/badapple_img:start`) で、2 つのアドオンを同時に入れてもぶつかりません。.vox と MMD は元の映像のコマが無いので使いません。作れなかったときはログに理由を出し、ブロックモードのアドオンはそのまま残ります。

| | Windows 版 | ブラウザ版 |
|---|---|---|
| 1 コマの大きさ | 横 256 画素、縦は画面の縦横比から | ブロックモードと同じコマ (幅 × 高さの画素) |
| fps | 30。テクスチャが予算を超えたら 15 → 10 に下げて作り直す | ブロックモードと同じ fps |
| 音声 | ffmpeg で 4 秒ごと | ブロックモードと同じ 10 秒ごとの OGG |
| 対応する Minecraft | 1.26.10 以降 | 1.26.10 以降 (古い版向けを選んでいるときは作らない) |

ゲーム内: `/bvpimg:setup [動画ID]` → `/bvpimg:start`。ほかに `play <動画ID>`・`pause`・`resume`・`stop`・`seek <秒>`・`volume <0〜100>`・`stats`・`list` (`/scriptevent bvpimg:<操作>` でも可)。
**時計**を使うか `remote` で、ブロックモードと同じリモコンが開きます (ブロックモードのリモコンはコンパス)。`setup` には `face` (向きを東西南北にそろえる)・`wall` (見ているブロックの横の面に貼る)・`align` (ブロックの格子にそろえる) を付けられます。メッセージは 10 言語です。

## 明るさ・縮め方・シートの詰め方

| オプション | 既定 | 内容 |
|---|---|---|
| `--lighting bright\|world` | `bright` | `bright` は周りの光と陰で暗くならない (render controller の `ignore_lighting`)。実機で、昼も夜も同じ明るさになることを確かめた。`world` は v6.36.0 までと同じ (夜はほぼ見えない) |
| (縮め方) | — | Windows 版・コマンドラインは、元の動画をコマに縮めるとき面積平均 (`flags=area`) で縮める。テスト映像で PSNR 37.26 → 37.38 dB、パック −24%。拡大は今までどおり。ブラウザ版の画像モードはブロックモードと同じコマを使うので、ブロックモードの出力を変えないよう、縮め方は v6.36.0 のまま |
| `--snap` / `--no-snap` | 使う | 頼んだ大きさの 9 割以上で、元の動画をちょうど割り切れる大きさにして、シート 1 枚に入るコマを増やす (1920×1080 で 512×288 → 480×270、シート 18 → 13 枚、テクスチャ −15%、パック −12%)。画質は既定と同等以上: テスト映像で PSNR 37.38 → 37.63 dB、粒子を足した実写に近い映像で 37.67 → 37.81 dB (SSIM は ±0.0006)。割り切れない大きさ (510×286 など) は輪郭のはっきりした映像で −1.6 dB になるので選ばない。元の大きさが分からない・縦横比が違う・1 割より大きく縮めないと増えないときは、頼んだ大きさのまま。ブラウザ版はコマの大きさが決まっているので使わない |
| `--png-optimize` | 切る | シートの PNG を最適化 (パック −3%、変換が数倍遅い) |

Windows 版の画面では「明るさ」「シートに多く詰める」「PNG を最適化」、ブラウザ版の画面では「明るさ」「PNG を最適化」を選べる。

動画のメタデータの `lighting` が無い (v6.36.0 までの) アドオンは `world` として扱う。`image_main.js` は変えていない。

## 予算を超えるとき (何を優先するか)

`--priority quality|smooth|length` (Windows 版は「優先」の選択) で、テクスチャが予算 (`--target-tier`、既定 2) を超えるときに何を守るかを決めます。

| 優先 | 変えるもの | 例: 512×288・30 fps・60 秒を Tier 2 (225 MB) に |
|---|---|---|
| 画質 (quality) | fps を下げる。足りなければ後ろを切る | 512×288・10 fps・約 38 秒 |
| なめらかさ (smooth) | コマを小さくする | 226×128・30 fps・60 秒 |
| 長さ (length) | fps とコマを交互に下げる | 314×176・15 fps・60 秒 |

計算は image_mode/budget.py (動画を読まずに数える)。Windows 版では「1 つのファイルにまとめる」で、ブロックモードの .mcaddon の中に画像モードのパック (`BP_image/`・`RP_image/`) も入れられます。ブラウザ版はまだどちらも選べません (コマはブロックモードと同じ大きさ)。

## 方式 A と方式 C

既定は方式 A だけです (2026-11-12 の実機の確認で A に決めました)。`--method both` で両方のエンティティを入れると、`/bvpimg:method a|c` で同じ場所・同じ再生位置のまま切り替えて見比べられます。テクスチャは共有します。

- **方式 A** (既定): アトラス + textures 配列 + 1 マス 1 ボーン + part_visibility。マテリアルを変えず、文書にある機能だけを使います。マスの数だけボーンがあり、その負荷は未確認です。
- **方式 C**: `USE_UV_ANIM` を足した自作マテリアル (`bvp_uv_anim:entity_alphatest`) + uv_anim。ボーンは 1 本です。
  **⚠ 将来の Minecraft の更新で壊れるリスクがあります。** Microsoft Learn は自作マテリアルについて「将来、非推奨または削除される可能性がある」と書いており、Vibrant Visuals で動くかも未確認です。

## テクスチャメモリ

テクセル数 × 4 バイトで数えます (Microsoft Learn の Texture Budgets)。変換時に Tier ごとのアドオンの予算 (Tier 1 150 MB 〜 Tier 5 800 MB) と比べた表を出し、Tier 2 (多くのスマートフォン・PS4・Xbox One) を超えると警告、Tier 5 を超えると `--allow-over-budget` が無ければ止めます。例: 256×144・30 fps・20 秒で約 97 MiB。

## 同期と限界

スクリプトは 1 秒ごとに「今のコマ」と通し番号をエンティティのプロパティに書き、クライアントはそこから自分の時計で進めます。チャンクの読み直しやワールドの開き直しの後は、最後に書いたコマから進め直し、次の書き直し (1 秒以内) で戻ります。時計はスクリプトが再生中に数える tick で、1 秒ごとに保存するので、開き直すと続きから戻ります (眠る・`/time set` の影響を受けません)。音声は 4 秒ごとのチャンクで、途中からは鳴らせないため、一時停止・シーク・途中参加の後は次の境目まで無音です。

詳しい取り決めは [image_mode/SPEC.md](../image_mode/SPEC.md)、調査の根拠はフェーズ 1 の報告にあります。
