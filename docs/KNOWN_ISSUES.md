# 既知の問題と回避策 / Known issues and workarounds

## 再生 (Minecraft)

| 問題 | 原因 | 回避策 |
|---|---|---|
| 色の多い映像で映像が遅れ、音声が途中で無音になる (v6.5.1 以前) | 座標リストの描画が色ごとに処理を区切り、1 フレームが何 tick にもまたがっていた。音声は 10 秒ごとに映像の位置で鳴らすので、映像が遅れるとその間が無音になる | v6.5.2 で修正 (ブロック 500 個ごとに区切る)。古い版では `/scriptevent <接頭辞>:render rect` で箱の描画に固定すると軽くなる |
| 再生が重い・カクつく・映像が音声より遅れる | 1 tick (50 ms) に置けるブロックには限りがあり、画面の大部分が変わる場面では次のフレームに間に合わない。映像が遅れても音声は実時間で進むので、次の 10 秒の区切りで音声を映像の位置から鳴らし直すまでずれが残る | 幅・高さ・fps を下げる (GUI の「再生負荷の目安」が「重い」なら下げる)。`/scriptevent <接頭辞>:stats` で遅れたフレーム数と映像の遅れを確かめられる ([PERFORMANCE.md](PERFORMANCE.md)) |
| 立体が描画の途中で一瞬欠けて見える (v6.5.0 以前) | 1 フレームで変わるブロックが多いと描画が何 tick にもまたがり、古い面を空気にしてから新しい面を置いていた | v6.5.1 で、新しいブロックを先に置いて空気にするのを最後にした (途中は一瞬厚く見える) |
| 2.5D のレリーフで、前の場面の柱がしばらく残る (v6.18.0 の実機の録画、原因調査中) | 実機で一部のブロックを空気にできず、置き直しも十数秒続けて失敗していた (モックでは同じアドオンがデータどおりに表示される)。v6.18.1 から、置けなかったブロックがあると再生ごとに 1 回、理由のエラーをチャットに表示する | チャットに出た理由を Issue で知らせてもらえると助かります。`/scriptevent <接頭辞>:stop` で消してから再生し直すと消える |
| 2.5D・立体が重い場面で遅れる (v6.18.1 以前) | 盤面の走査の区切りを、1 tick に置くブロック数の上限の回数に数えていた | v6.18.2 で修正 |
| だまし絵が一部の人にはゆがんで見える・横に回ると描き直されない | だまし絵は、舞台の中央に一番近いプレイヤー 1 人の目から見たとおりに描く。描く面は床と後ろ・左・右の壁なので、箱の外の横からは描けない | 見る人を 1 人にする。箱の中か手前から見る |
| MMD の髪やスカートが揺れない・表情が変わらない | 物理 (剛体) と表情 (モーフ) は計算しない。髪やスカートは体に付いたまま動く | 揺れ方の分かる踊りなら、MMD 側で物理を焼き込んだ (ボーンのキーフレームにした) モーションを使う |
| 人物の切り抜きが欠ける・余計な所まで立体になる | AI の切り抜き (DeepLabV3) は、人物が小さい・暗い・背景と似た色だと外れやすい。写真で学習したモデルなので、アニメや 3DCG の MV では形が丸くつぶれ、全身が小さく映る場面の人物を見落とし、強い光を人物と取り違えることがある。アニメ向けのモード (anime-seg) は 2D のアニメ・イラストでは髪の先まで正確だが、3DCG の強い照明の場面や全身が小さい場面では何も返さないことがあり、GPU があればそのフレームは目立つ物の切り抜き (BiRefNet_lite) のうち人物らしい塊、GPU が無ければ実写向きのモデルの粗い形になる。とても小さく映った人物は、どちらでも見落とすことがある。カメラが動く映像では、背景の消し跡がぼやける | 人物が大きく映っている映像を使う。人物の範囲の動画 (`scripts/make_person_videos.py`) を自分で直して `--mask-video` に渡すこともできる |
| スクリーンが床に寝ている (映像の面が上を向く)・思った向きにならない | `setup` は北向きに置く: 平面は足元から北東へ広がる床置き、立体は 2 ブロック北に南向き。`setup align` はチャンクにそろえて位置をずらすだけで、向きは変えない | 見たい方向を向いて `setup wall` (平面をテレビのように立てる) か `setup face` (床置きのまま、見ている方向へ広げる。立体・だまし絵もこちらを向く) を使う (v6.29.0 から) |
| 再生しても音が出ない | 主な原因: (1) 動画に音声が入っていない (変換時に音声を取り出せなかった。v6.29.0 からは再生時にチャットで知らせる)、(2) リソースパックが有効になっていない (音声はリソースパックに入っている)、(3) リモコンの音量設定が 0%、(4) ゲームの設定の「サウンド」の音量 (主音量など) や端末の音量・消音、(5) アドオンを読み込んだ後にゲームを再起動していない (新しい音声が読み込まれないことがある) | ワールドの設定でリソースパックが有効か確かめ、リモコンの 🔊 音量を上げ、ゲームと端末の音量を確かめる。Minecraft を一度終了して起動し直す。音声の入った動画で作り直す (ブラウザ版はブラウザが動画の音声を読めないと「音声なし」になる。変換ログを確かめる)。スマートフォンでは確かめられていないので、直らなければ [Issue](https://github.com/ntk758/MinecraftAddon_Bedrock_Video-Player/issues/new/choose) で知らせてください |
| setup の直後に再生すると、最初の画面に穴が開き「ブロックを置けませんでした (読み込まれていないチャンク)」と出る (v6.29.1 以前) | 常時読み込み (tickingarea) の登録が効く前に再生が始まっていた | v6.29.2 で修正 (チャンクが読み込まれるまで最大 10 秒待つ)。古い版では、setup の後に数秒待ってから再生する |
| スクリーンの範囲のブロックが消える | スクリーン (立体) の範囲は上書きされる。元に戻す機能は無い | 平らで何もない場所 (スーパーフラットなど) で `setup` する |
| 遠くに行くと再生が止まる・画面が欠ける | 読み込まれていないチャンクにはブロックを置けない。アドオンは常時読み込み (tickingarea) を登録するが、Minecraft の上限 (ワールド全体で 10 個) と、このアドオンの上限 (8 個) がある | スクリーンの近くで見る。ほかのアドオンや `/tickingarea` で上限を使い切っていないか `/tickingarea list` で確かめる |
| 立体が下にずれて置かれる | 建築できる高さ (オーバーワールドは Y=-64〜319) からはみ出すため、自動で下げている (チャットに表示) | もっと低い場所で `setup` するか、高さを下げて作り直す |
| 作り直したアドオンが更新されない / 同じパックが 2 つ並ぶ | パック名とコマンド接頭辞が同じなら同じパック (UUID) として作られ、版はビルドごとに上がる。名前か接頭辞を変えると別のパックになる | ワールドの設定から古い方を外す。同じ名前・接頭辞のまま作り直す |
| 古い版のアドオンで新しい版の変換データを使うと表示が崩れる・再生されない | 変換データとアドオン (`main.js`) は同じ版で作る前提 (例: Phase 8.3 の 2.5D の立体のデータは、v6.3.0 以前のアドオンでは平らな画面になる。8.4 の `varint_rle_v6` は v6.5 以前のアドオンでは再生されない) | GUI で作った `.mcaddon` をそのまま使う (変換データとアドオンが常にそろう) |
| スマートフォン・ゲーム機で動くか分からない | 作者が確かめたのは Windows 版だけ ([COMPATIBILITY.md](COMPATIBILITY.md)) | 軽量・標準プリセットから試す。動いた・動かなかったを Issue で知らせてもらえると助かります |

## 人物の切り抜き (AI)・だまし絵の限界と、しなかったこと

| 問題 | 原因 | 回避策・理由 |
|---|---|---|
| アニメの切り抜きの出力と進み具合が 6 フレーム遅れる | 時間方向に安定させるため、6 フレーム先まで読んでから確定する (窓は最大 13 フレーム、640 × 360 で約 20 MB) | 仕様。変換は一度きりで再生には影響しない |
| 予備のモデルに頼るフレームが多い場面で、人物の大きさが跳ぶことがある | アニメ向けのモデルが人物を見つけない場面 (3DCG の強い照明・全身が小さい場面。ローカルのアニメ MV の 30 秒では、全 300 フレームのうち 186 フレーム (約 60%) で予備のモデルを使い、そのうち予備をそのまま使うのは 75 フレーム (約 25%) は、予備のモデルの結果を近くの人物の大きさに合わせる。合わせる元の人物が少ないと合わせ切れない | 全身が小さい場面は、人物が大きく映る動画を使う。アニメ向けのモデルが人物を見つける動画なら起きない。処理ログの注意 (予備のモデルが 50% 超・人物が空のフレームが 10% 超) が目安 |
| 見る人の目が人物の最前面のすぐ手前 (約 0.03〜0.12 ブロック) にあると、だまし絵の投影が大きく抜ける (数百〜千数百マス) | 投影が写る範囲を、角からの視線で求めているため。v6.28.0 からある。目が人物のブロックの並びの中や後ろにあるときの抜けは数マス (テストは xfail のまま) | 人物に顔をくっつけず、箱の中か手前に立つ。直すには、写る範囲を面の凸包と各壁の交差で求める別の変更が要る |
| 人物のいない動画で、予備のモデルが背景や光の筋を人物とした塊 (約 20 フレーム) は、検査で減らない | 予備の結果の検査は、近くに人物の位置の手がかりがある場面と、面積が上限 (画面の 60%) を超える結果だけを退ける。ローカルの人物のいない動画では 21 → 21 フレームのまま (退けた数 0) | 人物の映る動画を使う。気になるときは処理ログの注意 (予備のモデルが 50% 超) を目安にする |
| 開発用の bench の実行中に一時停止・シーク・再開をすると、bench が通知なしで中止される | bench のジョブが再生のジョブと同じ枠 (`currentJobId`) に入るため | 通常の再生には影響しない。bench の間は操作しない |
| 切り抜きの途中でやめるボタンが無い | GUI に切り抜きのキャンセルの機能が無い (子プロセスを終わらせる処理が無い) | 作成が終わるまで待つ。キャンセルは未対応 |
| メモリが足りないとき、推論の入力解像度を下げる段が無い | アニメ向けのモデル (ISNet) と補助モデル (BiRefNet) の入力は 1024 で固定なので、下げても推論のメモリは変わらない (写真向けのモデルのメモリは約 0.4〜0.5 GB で、もともと小さい)。段階は、補助モデルを外す・GPU から CPU・写真向けのモデルだけ、の順に軽くする | 入力に使う動画の長い辺 (切り抜きは既定 640) を小さくしても、推論のメモリはほぼ変わらない。メモリが足りないときは他のアプリを閉じる |
| 実物の GPU のメモリ不足 (887A0005 / E_OUTOFMEMORY) の動きは未検証 | 手元の GPU (16 GB) ではメモリを別に確保した状態で再現したが、実際の例外は起きず、DirectML が共有メモリへ退避して遅くなった。例外の経路は偽のセッションでだけ確かめた。DirectML が使うのは device 0 だが、空き VRAM は一番大きいアダプターで見ている | 切り抜きが遅い・止まるときは、環境変数 `BVP_PROFILE_NEEDS_GB` で要る空きを大きくして軽い段階から始める (例 `full=64:64`)。統計の `profile_reason` を見る |
| 長い動画の処理でメモリが増え続けないかは、実際の動画では測っていない | 連続して複数の動画を処理するテストは偽の ORT で、実機の長時間の測定は無い | 処理ログの最大のメモリ (`memory`) を見る。増え続けるときは Issue で知らせる |
| 深度推定 (Depth Anything V2) を使った立体化と、実写の人物の輪郭は評価していない | 深度を足すと形式と経路が変わり、投影の負荷が +33〜53% になる見込みで、見た目が良くなる測定も無く、必要なライブラリ (transformers) も入っていないため採用しなかった。実写の切り抜き (DeepLabV3) は v6.28.0 のまま変えていない | 実写は人物が大きく映る動画を使う。アニメ・3DCG はアニメ向けのモード |
| アニメの切り抜きの画質の確認は、ブロック単位のちらつきの指標だけ | 輪郭・細部の目視の比較や IoU・SSIM は、手元の第三者の動画 3 本では行っていない | ちらつき (1 フレームだけ変わるマス) と変わるマスは、ローカルのアニメ MV の GPU の段階で 7% と 2.5%、full で 15% と 9%、ダンス (10 fps) で変わるマスが 12% 減っただけ (1 回ずつの測定)。予備の結果を検査で退けた分、GPU の段階の MV は途中の測定より増えた。輪郭が良くなったとは言えない。気になるフレームは Issue で知らせる |
| 実機 (Minecraft) の FPS・TPS・フレーム時間の前後の比較が無い | 数値は Node のモックでの通し再生の値と、そこからの見積り (実機は約 3.1〜4.6 倍) だけ。見積りは実測ではない。モックの tick の最大は最終の測定で −33%〜+1.9% (±10% 以内はノイズ) | [TESTING.md](TESTING.md) の 2.1 の手順で、v6.28.0 とこの版を実機で測る |
| 写真向けかアニメ向けかを、動画ごとに自動で選ばない | 自動の判定は採らなかった (Phase B の検討)。手元の 15〜19 本のクリップで閾値を決めると過学習になるおそれがあり、8 フレームの判定は間違えやすく、判定に 6〜17 秒かかるため | 表示モードで選ぶ (アニメ・イラスト・3DCG の MV は「アニメの人物を切り抜いて立体に」)。重さの段階だけは空きメモリから自動で選ぶ |
| フレームの異常の判定は、面積 (空かどうか) と、予備の結果の面積の上限・位置の検査だけ | 指標を増やす (形・縁の長さ・前後との面積の比など) と、手元の動画にだけ合う閾値になるおそれがあるため採らなかった (Phase B の検討) | 処理ログの注意の行 (人物が空のフレーム 10% 超など) と、`/scriptevent <接頭辞>:stats` を目安にする |

## 変換 (PC)

| 問題 | 原因 | 回避策 |
|---|---|---|
| GPU があるのに CPU で変換される | PyTorch (または torch-directml) が無い、GPU のテスト変換に失敗した、CPU 専用のディザ (Floyd-Steinberg など) を選んだ | 処理ログの `Conversion device:` の行を確かめる。DirectML は Python 3.12 まで |
| GPU で変換しても速くならない | GPU 経路は OkLab での色合わせ・RDO などの処理が多く、変換全体は CPU と同じくらいのことがある | 時間が気になるときは CPU (`--device cpu`) も試す ([PERFORMANCE.md](PERFORMANCE.md) の変換速度) |
| 長い動画の変換に時間がかかる | 動き探索とタイル辞書 (4 と 8 の両方を試す) で 1 フレームずつ符号化している | ログの「残り約 m:ss」を目安に待つ。急ぐときは `--tile-size 8` (3〜4 割速く、データは 0〜1% 増える) |
| 16:9 の動画で上下に黒い帯ができる | 指定した幅・高さの中に縦横比を保って収めている | GUI の「動画の縦横比に合わせる」を押す (例: 128×128 → 128×72) |
| 羊毛・木材のブロックが燃える / ネザーラック・ソウルソイルの火が消えない | 全ブロック・自動パレットは燃えるブロック (羊毛・木材) も使う。ネザーラックとソウルソイルの上の火は消えない (スクリーンは空に面しているので雷でも着火しうる) | 火や溶岩の近くに置かない。燃やしたくないときはパレットを「39 色」以下にする |
| 夜にスクリーンの一部が光る | 「全ブロック」と「39 色」には光るブロック (シーランタン・フロッグライトなど) が入っている (自動パレットには入れていない) | 自動パレットか「拡張 33 色」以下を使う |
| 近くで見るとブロックの模様が目立つ | 石・羊毛・木材は模様のあるテクスチャ (色は平均で合わせている) | 少し離れて見る。模様の無いブロックだけにするならパレットを「基本 16 色」 (コンクリート) にする |
| iPhone のブラウザ版で変換すると「音声なし / no audio (Decoding failed)」になる (v6.29.0 以前) | iPhone の Safari・Chrome (WebKit) は MP4・MOV の動画ファイルを丸ごと音声としてデコードできない | v6.29.1 で修正 (動画から AAC の音声トラックだけを取り出してデコードする)。AAC 以外の音声の動画は、PC のブラウザか Windows 版で変換する |
| 音声が映像より短い動画を、長さを指定せず (`--duration` なし) AI で人物を切り抜くと、`OSError` で失敗するか、人物を消した背景の動画がマスクより短くなる (v6.28.0 以前から同じで、まだ直していない) | 背景の動画を書く ffmpeg に `-shortest` を付けているため、音声が尽きると ffmpeg が先に終わり、残りのフレームを書き込めない (パイプが閉じて `BrokenPipeError` (`OSError`、errno 32)。手元の確認では、音声 1 秒・映像 4 秒の動画で起き、背景は 10 フレームで切れた)。書き込みがパイプの余裕に収まるほど短い動画では、エラーにならず背景だけ短く出来上がる | 長さ (秒) を指定する (音声の入力だけをその長さで切るので、映像のフレームは落ちない)、または音声を映像の長さに延ばした動画に直してから読み込む。GUI は `OSError` を落ちたものとして扱い (終了コードは 1)、重い設定から軽い設定へ順に最大 4 回やり直し、どれも同じ理由で失敗して、「人物の切り抜きが、いちばん軽い設定でもできませんでした」と末尾 400 文字の詳細・ログの場所を出す。短い背景になったときは GUI は気づかず、そのまま作る |
| 「ffmpeg が見つかりません」 | ffmpeg が PATH に無い (EXE 版にも FFmpeg は入っていない) | `winget install Gyan.FFmpeg` で入れるか、`ffmpeg.exe` をツール (EXE) と同じフォルダに置く |

ここに無い問題は [Issue](https://github.com/ntk758/MinecraftAddon_Bedrock_Video-Player/issues/new/choose) で知らせてください。
