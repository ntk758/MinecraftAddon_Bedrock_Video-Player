# 色の境界の崩れ方と、8×8 の継ぎ目 (2026-11-16)

「ディザで色の境界がおかしくなる」を、崩れ方の 3 種類に分けて測り、一番はっきり出た 8×8 の最適化 (`mvcodec/block_rdo.py`) の継ぎ目を直した。
物差しは `benchmark/edge_bench.py`。実機の見た目と合うかは未確認 (TODO の P2-2)。

## 測り方

- 手元の 21 本 (Xiph 11・Tears of Steel 4・NASA 3・合成 3)。128×72、10 fps、各 40 コマ (2 コマおきに評価)、自動パレット、CPU。
- 見え方は S-CIELAB のぼかし、距離はスクリーンの高さの 2 倍 (`benchmark/metrics/dither_view.py` と同じ)。
- 境界は、元のフレームで隣のマスとの ΔE76 が 12 以上の所。帯は境界から 1 マス以内、内側は 4 マス以上離れた所。
- **にじみ**: ぼかした絵の色差 (帯 / 内側) と、境界のコントラスト (ぼかした絵の 3×3 の明るさの幅、表示 / 元)。
- **粒・場違いな色**: 足された粒 (帯 / 内側)。3×3 のまわりのどの元の色とも ΔE76 が 15 を超えるマスの割合。
- **8×8 の継ぎ目**: 8×8 の区切りのうち、片方が 1〜2 色だけでもう片方が 3 色以上、かつ元の映像ではそこに境界が無い線。
  線の両側 2 マスの平均の色の差が元から ΔE76 3 以上ずれた線の割合。対照はディザのある 8×8 どうしの線。
- 閾値 (12・15・3) は目安で、視覚実験の根拠は無い。

## 直す前 (v6.38.0、21 本の平均)

| | 色差 帯 / 内側 | コントラスト | 粒 帯 / 内側 | 場違いな色 帯 / 内側 | 継ぎ目 (平ら↔ディザ / 対照) | データ |
|---|---|---|---|---|---|---|
| Blue Noise | 7.04 / 6.86 | 1.02 | 4.15 / 4.04 | 8.4% / 10.1% | **39.7%** / 36.3% | 1.66 MB |
| Blue Noise、8×8 の最適化なし | 6.80 / 6.84 | 1.02 | 4.10 / 3.95 | 8.2% / 9.5% | **18.5%** / 30.6% | 1.80 MB |
| Floyd | 7.34 / 7.25 | 1.04 | 4.95 / 4.33 | 12.2% / 14.2% | **44.8%** / 31.5% | 1.75 MB |
| Floyd、8×8 の最適化なし | 7.14 / 7.34 | 1.04 | 4.76 / 3.65 | 11.6% / 12.1% | **18.4%** / 23.7% | 1.92 MB |
| ディザなし | 6.79 / 6.97 | 0.99 | 3.09 / 2.10 | 5.9% / 5.6% | 25.5% / 27.0% | 1.52 MB |

- にじみは無い。粒と場違いな色も、実写では境界に集まっていない。
- 8×8 の最適化が平らにした区画とディザのある区画の境目で、ずれる線が倍以上になる。
- 合成の映像 (スライド・ネオン・歌詞) は境界の場違いな色が 11〜33% と多いが、ディザなしでもほぼ同じ (9〜32%)。原因はパレット (近い色のブロックが無い) と縮めたこと。

## 原因と直し方

8×8 の最適化は、候補の色の誤差を 3×3 でぼかした差で測る。3×3 ではディザの粒が残るので、ディザのある「減色の結果」にも粒の分の誤差が付き、
平均の色が少しずれた単色・2 色の候補の方が良く見えていた。離れて見ると、ずれた平均の色がそのまま区画の色の段差 (継ぎ目) になる。

8×8 の平均の色 (OkLab ×100、色合い ×1.5) の元とのずれの二乗 × 画素数に `DC_WEIGHT` を掛けて、候補の誤差に足す。
1 つの 8×8 の誤差の上限 (`BLOCK_ERROR_CAP`) もこれを含めて判断する。`--block-rdo auto` の強さを決める予算は、今までの誤差で数える (データが増えすぎないように)。

### 重みの選び方 (12 本、128×72)

| DC_WEIGHT | 継ぎ目 Blue Noise | 継ぎ目 Floyd | データ |
|---|---|---|---|
| 0 (v6.38.0) | 49.1% | 48.7% | ±0 |
| 2 | 30.4% | 38.1% | +2.5% |
| **4 (採用)** | **27.3%** | **37.7%** | **+3.3%** |
| 8 | 26.7% | 36.0% | +4.1% |

4 より上はデータが増えるのに比べて、継ぎ目がほとんど減らない。

## 直した後 (21 本、Blue Noise)

| | v6.38.0 | 直した後 |
|---|---|---|
| 継ぎ目 (平ら↔ディザ) | 39.7% | **23.2%** |
| 継ぎ目の対照 (ディザ同士) | 36.3% | 34.7% |
| 遠目の色差 (k = 1 / 2 / 4) | 5.50 / 5.17 / 4.50 | 5.46 / 5.12 / 4.43 (−0.7% / −0.9% / −1.4%) |
| ぼかした CIEDE2000 | 3.72 | 3.63 (−2.4%) |
| 残って見える粒 (k = 2) | 4.03 | 4.13 (+2.4%) |
| ちらつき (静止のある 11 本) | 0.0010 | 0.0011 |
| データ | 1.66 MB | 1.71 MB (+2.8%) |
| 1 フレームの描画時間の見積り | 3161 µs | 3212 µs (+1.6%) |

- 遠目の色差 (k = 2) は 21 本のうち一番悪くなった映像でも +0.3%、一番良くなった映像で −4.6%。
- 継ぎ目が大きく減ったのは、木 (70% → 10%)・古い町 (69% → 26%)・顔 (57% → 20%)・ロケット (57% → 0%) など。
  運河 (69% → 60%)・アヒル (57% → 60%)・歌詞 (41% → 39%) はほとんど変わらない。
- Floyd は 44.8% → 35.0%、データ +2.8%。
- 粒が少し増えるのは、平らにする 8×8 が減る (13.9% → 11.8%) ため。8×8 の最適化を切ったとき (データ +8.6%) と同じ向き。

## 限り

- 128×72 だけ。物差しが実機の見た目と合うか (P2-2) は未確認。Minecraft で継ぎ目が減って見えるかも未確認。
- 2.5D の色の平面にも同じ式がかかる (空の列は平均に数えない)。2.5D での評価はしていない。
- 再現: `python benchmark/edge_bench.py --videos <動画…> --out <出力> --variants blue_noise floyd`。
