# 自動パレットの色空間 (RGB / OkLab) と色数の比較 (Issue #3)

## 追記: 候補を 112 色に増やし、色を実測の値にした (v6.4.0 の後)

v6.4.0 までのブロックの色は目安の値 (Java 版の地図の色に近く、白いコンクリートが (255, 255, 255)、黄色が (229, 229, 51) など) で、
実際の見た目と大きくずれていました。Mojang 公式の bedrock-samples (1.26.50.4) のテクスチャの上面を線形の明るさで平均した色に置き換え、
候補を 112 色に増やしました (`scripts/generate_block_colors.py` → `mvcodec/block_colors.py`)。

- 候補の条件: 1 マスの不透明な立方体、重力で落ちない (砂・砂利・コンクリートパウダーを除く)、時間で変化しない (ろう引きしていない銅・
  生きたサンゴ・氷・草を除く)、まわりに作用しない (マグマ・レッドストーンブロックを除く)、面ごとの見た目の差や模様が小さい
  (原木・彩釉テラコッタ・鉱石を除く)、1.21.80 にもある。金・ダイヤモンド・エメラルド・ネザライトのブロックは、サバイバルで
  スクリーンを掘ると資源になるので除く。色がほとんど同じもの (OkLab の距離 × 100 が 2 未満) は 1 つに絞る (コンクリート優先)。
- GUI の既定は自動パレット (112 色からシーンごとに最大 64 色、RGB で選ぶ)。

同じ条件 (128×72、60 フレーム、CPU) で、v6.4.0 の 39 色 (`--palette full`、古い色の値で減色) と比べた結果です。
見た目はどれも実測の色で評価しています (ゲームの中で実際に見える色)。

---

以下は候補が 39 色だったとき (v6.4.0) の比較です。

`--palette auto` は GOP ごとに映像の色を K-Means でまとめ、各代表色に一番近いブロックを選びます。
この選び方を OkLab (知覚的に均等な色空間) で行うと色の再現が良くなるか、色数を減らすと何が変わるかを測りました。

- 再現: `python benchmark/palette_bench.py --out bench_out` (合成映像 128×72、60 フレーム、10 fps、CPU で減色)
- 指標: ΔE2000 (画素ごとの色差の平均、小さいほど良い)、MS-SSIM (明るさの構造、大きいほど良い)、
  変化率 (1 フレームで変わる画素の割合 ≒ 置くブロックの割合)、データ (出力 .js の deflate 後)
- `full (39)` は全 39 色の固定パレット。`auto N rgb/oklab` は色数の上限 N の自動パレット (`--palette-colors N --palette-space rgb/oklab`)

## 結論

1. **既定の自動パレット (上限 64 色) では、色空間を変えても結果は同じ**。候補のブロックが 39 色しか無いので、
   全部のブロックが選ばれ、並び順しか変わりません (データの差は 1% 未満)。Issue で想定していた効果は、
   候補より少ない色数を選ぶときにしか現れません。
2. **色数を 16 に減らすと、データは 2〜34% 減る** (RGB で選んだ場合。Blue Noise のアニメ風で 29.1 → 20.0 KB、ディザなしのグラデーションで 16.9 → 11.1 KB、ディザなしのパンは −2%)。色差の悪化は
   ΔE2000 で +0.5 以内の映像が多い一方、色の多いグラデーションでは +1.4 (Blue Noise) と目に見えて粗くなります。
3. **16 色での OkLab は映像によって良し悪しが分かれる**。パンでは色差・変化率・データがすべて良くなった
   (16 色の RGB と比べて、ディザなしでデータ −32%・変化率 0.059 → 0.046、Blue Noise でデータ −20%・変化率 0.051 → 0.041) が、testsrc2 では MS-SSIM が 0.870 → 0.838 に下がりました
   (明るさの差より色味の差を重く見て、明るさの段階が減るため)。24 色ではほぼ同じです。
4. そのため **既定は RGB のまま** にし (出力は変わらない)、`--palette-space oklab` と `--palette-colors` を
   選べるようにしました。

## 注意

- 合成映像だけの結果です。実写では色の分布が違うので、実映像での確認が必要です (TODO 8.8)。
- ffmpeg の `gradients` は実行ごとに模様が変わるため、比較には変換に使った保存済みのフレームを使っています。
- 候補のブロックを増やせば (重力で落ちない色付きブロック)、上限 64 色でも選び方の差が出るようになります。
