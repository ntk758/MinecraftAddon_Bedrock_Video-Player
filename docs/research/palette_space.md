# 自動パレットの色空間 (RGB / OkLab) と色数の比較 (Issue #3)

## 追記: 候補を 108 色に増やし、色を実測の値にした (v6.4.0 の後)

v6.4.0 までのブロックの色は目安の値 (Java 版の地図の色に近く、白いコンクリートが (255, 255, 255)、黄色が (229, 229, 51) など) で、
実際の見た目と大きくずれていました。Mojang 公式の bedrock-samples (1.26.50.4) のテクスチャの上面を線形の明るさで平均した色
(アニメーションは全コマの平均) に置き換え、候補を 108 色に増やしました (`scripts/generate_block_colors.py` → `mvcodec/block_colors.py`)。

- **候補の条件**: 1 マスの不透明な立方体、重力で落ちない (砂・砂利・コンクリートパウダーを除く)、時間で変化しない
  (ろう引きしていない銅・生きたサンゴ・氷・草を除く)、まわりに作用しない (マグマ・レッドストーンブロックを除く)、
  面ごとの見た目の差や模様が小さい (原木・彩釉テラコッタ・鉱石を除く)、1.21.80 にもある。
- **資源・経験値になるブロックは除く**: スクリーンは変わったブロックを毎フレーム置き直すので、サバイバルで掘ると
  無限に得られてしまう (金・ダイヤモンド・エメラルド・ネザライト・鉄・ラピスラズリ・石炭のブロックとその原石、スカルク)。
- **光るブロック** (シーランタン・グロウストーン・シュルームライト・フロッグライト 3 色・泣く黒曜石) は「全ブロック」
  (`--palette all`、108 色) には入れるが、**自動パレットの候補 (101 色) には入れない**。置き替えるたびに明るさの計算が起き
  (負荷は実機で未計測)、夜はスクリーンの明るさがまだらになるため。
- 色がほとんど同じもの (OkLab の距離 × 100 が 2 未満) は 1 つに絞る (模様の無いコンクリートを優先)。
- **GUI の既定は自動パレット** (101 色からシーンごとに最大 64 色、RGB で選ぶ)。

### v6.4.0 の既定 (拡張 33 色) との比較

同じ条件 (128×72、60 フレーム、CPU) で、v6.4.0 の GUI の既定 (`--palette expanded`、古い色の値で減色) と、新しい既定 (自動 64 色) を
比べました。見た目はどちらも実測の色で評価しています (ゲームの中で実際に見える色)。GUI の既定のディザは Blue Noise です。

- 色差はすべての映像で 18〜62% 減りました (既定の Blue Noise では 26〜58%)。
- データと 1 フレームで変わるブロックは多くの映像で増えます。Blue Noise では −3〜+30% ですが、ディザなしで細かい模様が
  横に流れるパンでは 2.2 倍になりました (色が増えて、似た色の境目が細かくなり、動き補償も効きにくくなるため)。
  データやブロックの数を抑えたいときは、パレットを「拡張 33 色」に戻すか、`--palette-colors` で色数を減らしてください。
- 光るブロックを候補に入れると、白っぽい映像の色差はもう少し下がります (グラデーション・ディザなしで 11.92 → 9.66、`--palette all`) が、
  上の理由で既定では入れていません。全部の色を使うなら `--palette all` です (データは自動 64 色より −2〜+16%)。
- 101 色の候補から OkLab で選ぶと、パンでは良くなる (ディザなしで ΔE 11.33 → 10.42、データ 52.1 → 38.3 KB) 一方、
  アニメ風では悪くなる (ΔE 6.91 → 9.67) ので、既定は RGB のままです。
- 色を実測の値に直しただけ (同じ 39 色、`--palette full`) でも、色差が 0.1〜5.7 下がりました (Blue Noise のグラデーションで 18.4 → 12.7)。
- ゲームの中でブロックを置く費用 (色が増えると同じ色の箱が小さくなり、`fillBlocks` の呼び出しが増えうる) は、まだ実機で測っていません。

再現: `python benchmark/palette_bench.py --out bench_out --baseline v6.4.0`

---

以下は候補が 39 色だったとき (v6.4.0) の比較です。

`--palette auto` は GOP ごとに映像の色を K-Means でまとめ、各代表色に一番近いブロックを選びます。
この選び方を OkLab (知覚的に均等な色空間) で行うと色の再現が良くなるか、色数を減らすと何が変わるかを測りました。

- 再現: `python benchmark/palette_bench.py --out bench_out` (合成映像 128×72、60 フレーム、10 fps、CPU で減色)
- 指標: ΔE2000 (画素ごとの色差の平均、小さいほど良い)、MS-SSIM (明るさの構造、大きいほど良い)、
  変化率 (1 フレームで変わる画素の割合 ≒ 置くブロックの割合)、データ (出力 .js の deflate 後)
- `full (39)` は全 39 色の固定パレット。`auto N rgb/oklab` は色数の上限 N の自動パレット (`--palette-colors N --palette-space rgb/oklab`)

## 結論

1. **既定の自動パレット (上限 64 色) では、色空間を変えても結果は同じ**。候補のブロックが 39 色しか無いので、
   全部のブロックが選ばれ、並び順しか変わりません (データの差は 1% 未満)。Issue で想定していた効果は、
   候補より少ない色数を選ぶときにしか現れません。
2. **色数を 16 に減らすと、データは 2〜34% 減る** (RGB で選んだ場合。Blue Noise のアニメ風で 29.1 → 20.0 KB、ディザなしのグラデーションで 16.9 → 11.1 KB、ディザなしのパンは −2%)。色差の悪化は
   ΔE2000 で +0.5 以内の映像が多い一方、色の多いグラデーションでは +1.4 (Blue Noise) と目に見えて粗くなります。
3. **16 色での OkLab は映像によって良し悪しが分かれる**。パンでは色差・変化率・データがすべて良くなった
   (16 色の RGB と比べて、ディザなしでデータ −32%・変化率 0.059 → 0.046、Blue Noise でデータ −20%・変化率 0.051 → 0.041) が、testsrc2 では MS-SSIM が 0.870 → 0.838 に下がりました
   (明るさの差より色味の差を重く見て、明るさの段階が減るため)。24 色ではほぼ同じです。
4. そのため **既定は RGB のまま** にし (出力は変わらない)、`--palette-space oklab` と `--palette-colors` を
   選べるようにしました。

## 注意

- 合成映像だけの結果です。実写では色の分布が違うので、実映像での確認が必要です (TODO 8.8)。
- ffmpeg の `gradients` は実行ごとに模様が変わるため、比較には変換に使った保存済みのフレームを使っています。
- 候補のブロックを増やせば (重力で落ちない色付きブロック)、上限 64 色でも選び方の差が出るようになります。


## 全ブロックへの拡充と側面の色 (v6.10)

`scripts/generate_block_colors.py` が、bedrock-samples の blocks.json の全ブロックから候補を自動で集めるようにした。立方体でない形 (階段・ハーフ・柵・花など)、重力で落ちるもの (砂・砂利・コンクリートパウダー)、時間で変わるもの (酸化する銅・溶ける氷・覆うと土になる草・枯れるサンゴ・消える葉)、まわりに作用するもの (TNT・レッドストーン・観察者・ディスペンサー・スポンジ・マグマ・虫食いブロック) を名前で除き、上面か側面のテクスチャに透明な画素があるもの (ガラス・格子・花) を除く。以前は「サバイバルで掘ると資源が得られる」ブロック (鉱石・金属のブロック) も除いていたが、チートを有効にして使うアドオンなので入れた。雪のブロックは光るブロックの明かりで溶けるので、光るブロックを含まない自動パレットにだけ入れる。

- 不透明なブロック 108 → 197 色 (自動パレットの候補 101 → 190 色)。1 つのパレットは 127 色までなので、「全ブロック」は上面と側面の色が互いに一番離れる 127 色を選ぶ。
- 各ブロックの上面と側面の色を測り、平面スクリーンは上面、立体 (relief / extrude / inflate / vox) は側面の色で選ぶ。原木は樹皮の色、幹・骨ブロック・柱なども立体に使える。
- 自動の色数の候補を 24〜64 から 24〜127 色にした (色の誤差の基準も 127 色に)。

v6.9.0 と比べて (128×72・Blue Noise・既定の設定、合成 5 本 + 実映像 3 本):

| 映像 | 色数 (最大) | 色差 ΔE2000 | データ | 描画時間 |
|---|---|---|---|---|
| アニメ風 | 24 → 24 | 7.40 → 6.88 (−7%) | +0% | −0% |
| パン | 24 → 24 | 11.72 → 9.80 (−16%) | −2% | +3% |
| testsrc2 | 24 → 24 | 15.78 → 15.13 (−4%) | +7% | −0% |
| mandelbrot | 32 → 48 | 13.37 → 9.98 (−25%) | −7% | +6% |
| シルエット | 24 → 24 | 2.60 → 2.60 (0%) | +0% | +0% |
| 実写 | 32 → 48 | 7.28 → 6.53 (−10%) | +11% | +17% |
| CG 予告編 | 32 → 48 | 5.52 → 5.15 (−7%) | +7% | +5% |
| アニメ予告編 | 64 → 64 | 7.60 → 6.67 (−12%) | +11% | +2% |

色差は平均 −10%、データは平均 +3%、描画時間は平均 +4% (色の多い実写で +17%)。候補が増えたぶん、近い色のブロックが選べるようになった。
